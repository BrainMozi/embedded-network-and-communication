# 现场演示操作卡

目标：**在 VS Code 按一次 Ctrl+Shift+B 启动，一块面板完成展示**。不必手工敲终端命令、不必现场跑测试或开第二个抓包窗口；面板已经显示实际 CAN 帧和 ECU 事件。

## 演示前启动：只用 VS Code 操作

1. 打开 VMware 中的 Ubuntu 与 VS Code。
2. 在 VS Code 选择 **File → Open Folder**，打开 `can_lighting_demo/` 项目文件夹。
3. 确认 VS Code 使用项目里的 `.venv/bin/python`（右下角 Python 解释器）。
4. 按 **Ctrl+Shift+B**，选择默认任务 **启动 CAN 灯光演示（Python）**。
5. VS Code 会自动准备 `vcan0`、运行项目 `.venv` 中的 Python、启动独立灯光 ECU 和控制面板，并打开本机浏览器。等页面显示 **ECU 在线**。

程序运行日志会显示在 VS Code 集成终端里，但你不需要在里面输入任何命令。结束时点该终端右上角的停止/垃圾桶按钮，或在任务菜单中选择 **Terminate Task**。

## 推荐现场顺序

1. **先复位**：点击“清故障并全关”，确认所有灯灭、ECU 在线。
2. **演示转向互斥**：点“左转向”，观察左灯亮、`0x256` 出现、事件时间线走完；再点“右转向”，观察左灭右亮。
3. **演示双闪**：点“双闪切换”，左右同时闪；再点一次关闭。
4. **演示其它灯与总控**：依次点刹车灯、前大灯、尾灯切换；最后点“全部开启”，再点“全部关闭”。
5. **演示异常闭环**：在下方勾选“刹车灯”虚拟故障，再点“刹车灯切换”；面板会显示目标状态与实际状态不一致及故障回报。点击“清故障并全关”恢复安全状态。
6. **收尾**：让面板停在全关状态；回到 VS Code 停止运行中的任务。

## 讲解时只抓住这条主线

> 点击命令 → 控制端发 `0x256` → ECU 接收并写入缓冲区 → 命令解析/灯光任务执行 → ECU 用 `0x257` 回报状态 → 控制端按序号确认。

- CAN 帧的 ACK 只说明帧级接收，不等于灯已经执行；以匹配序号的 `0x257` 状态回报作为应用层确认。
- `0x258` 仅是本项目的**仿真故障注入帧**，用于展示监控链路，不是课件规定的车辆控制 ID。
- 这是 `vcan0` 软件仿真；灯光图示是软件状态，不是实体灯具。

**备用查看方式：**如需原始帧抓包，可在 VS Code 里另开终端运行 `bash scripts/run_candump.sh`。常规展示不需要额外窗口，主面板已够用。
