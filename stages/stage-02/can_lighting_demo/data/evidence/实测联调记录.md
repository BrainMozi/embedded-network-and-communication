# CAN 灯光系统实测联调记录

## 环境与范围

- Ubuntu 26.04.1 LTS / Python 3.14.4 / `python-can` 4.6.1。
- Linux SocketCAN 虚拟接口 `vcan0`；独立 ECU 进程与控制台服务实际通过 CAN socket 通信。
- 验证的是软件灯态仿真与 Python 用户态任务，不是实体灯具测试或硬实时保证。

## 实测结果

在最终实现版本的同一运行会话内连续执行 2 轮完整 smoke test，合计发送 **32 条控制帧**：

| 指标 | 结果 |
|---|---:|
| 0x256 控制命令 | 32 |
| 正常状态确认 | 28 |
| 非法命令拒绝 | 2 |
| 故障状态回报 | 2 |
| 0x257 周期反馈接收 | 3004 帧 |
| 平均应用层闭环时间 | 12.2 ms |
| 自动重试 / 超时 / CAN 错误 | 0 / 0 / 0 |

测试覆盖：全开/全关、亮度参数、左右转向互斥、双闪优先与切换、刹车灯/前大灯/尾灯切换、虚拟刹车灯故障、非法命令拒绝、清故障与安全状态恢复；所有场景通过。全会话自动重试、超时与 CAN 错误均为 0。

另对左转命令核验了完整结构化事件链：`controller_command_sent → can_rx → command_parsed → lamp_applied → feedback_confirmed`；烟雾测试要求所有事件使用同一命令序号，并确认面板 HTML 和状态接口实际可访问。

## 原始证据

- `candump.log`：Ubuntu `candump -L -n 120 vcan0` 从最终实现运行中的 `vcan0` 抓取的 120 条真实虚拟 CAN 帧。
- `events.jsonl`：本轮 demo 的 ECU 与控制端结构化日志，包含缓冲区入队、解析、控制队列、执行、异常和应用确认事件。

现场复现方式：在 VS Code 打开项目文件夹，选择项目 `.venv/bin/python`，按 Ctrl+Shift+B 运行默认任务“启动 CAN 灯光演示（Python）”。烟雾测试脚本只用于开发验证，现场不需要手工运行。

**解释边界：**11.0 ms 是本次特定 VM 负载下的端到端观测均值，不是课件规定的验收阈值，也不能外推为实时上限。`vcan0` 不包含物理线路、CAN 收发器、总线仲裁竞争和真实灯具反馈。
